# Plano de Evolução do Portfólio — Anderson Faria

> Objetivo: transformar o portfólio atual em uma vitrine internacional de alta qualidade para oportunidades de **Software Quality Assurance**, **QA Automation**, **SDET**, **AI-assisted Testing** e futura evolução para **AI/ML QA Engineer**, com foco em **Holanda, Alemanha, Bélgica, Irlanda e interior do Reino Unido**.

---

## 1. Contexto do profissional

Anderson Faria atua como QA Engineer / Software Quality Analyst, com experiência em:

- Testes manuais e funcionais;
- Testes E2E;
- Testes de API com Postman, REST e GraphQL;
- Automação com Playwright, Cypress, TypeScript e JavaScript;
- CI/CD com GitLab;
- Jira, GitLab Issues, Scrum/Kanban;
- Sistemas públicos/federais e plataformas complexas;
- Sistemas com mapas, georreferenciamento, GeoServer/PostGIS e fluxos críticos;
- Documentação de QA, cenários, regressão, evidências e análise de bugs;
- Visão de produto, PO/PM e melhoria de processo;
- Interesse estratégico em AI-assisted Testing, AI/ML QA e QA para games.

O portfólio não deve exagerar nem inventar experiências. A proposta é **valorizar tecnicamente o que já existe**, organizar melhor a narrativa, melhorar design/arquitetura e abrir espaço para evolução futura.

- **SDET em evolução**;
- **Profissional preparado para times remotos/globais**;

## 3. Idiomas obrigatórios

O portfólio deve suportar três idiomas:

1. **English** — idioma principal para recrutadores internacionais;
2. **Português** — para mercado nacional e leitura natural do histórico;
3. **Nederlands / Dutch** — diferencial para Holanda e Bélgica.

### 3.1 Estratégia de idioma

Recomendação:

- Idioma padrão: **English**;
- Seletor visível no topo: `EN | PT | NL`;
- Não misturar idiomas na mesma página;
- Usar arquivos de tradução centralizados;
- Evitar tradução automática literal, principalmente em holandês;
- Textos em holandês podem ser mais curtos e objetivos no início, para reduzir risco de erro.

### 3.2 Estrutura técnica sugerida para i18n

Se o projeto usa Next.js, considerar:

- `next-intl`, `next-i18next` ou solução simples própria;
- Rotas sugeridas:
  - `/en`
  - `/pt`
  - `/nl`
- Alternativa mais simples:
  - Manter rota única e trocar conteúdo via estado/contexto, mas a abordagem com rotas é melhor para SEO.

### 3.3 Arquivos sugeridos

```txt
src/
  i18n/
    en.json
    pt.json
    nl.json
  config/
    site.ts
    navigation.ts
```

2. Contexto;
3. Problema;
4. Responsabilidades de QA;
5. Estratégia de teste;

7. Exemplos de cenários;
8. Evidências ou prints, se puder compartilhar;
9. Resultado/impacto;
10. Links para GitHub, demo ou documentação.

### 10.2 Template de case study

```md
## Project Name

### Context
Short explanation of the product/domain.

### Challenge
What quality problem needed to be solved?

### My Role
What Anderson did as QA.

### Testing Strategy
- Manual testing
- API validation
- E2E automation
- Regression coverage
- CI/CD integration

### Tools
Playwright, Cypress, Postman, TypeScript, GitLab CI/CD, etc.

### What I Delivered
- Test scenarios
- Automated test suite
- API collections
- Regression checklist
- Bug reports
- CI execution

### Impact
Describe concrete result if available. If not, describe qualitative impact honestly.
```
